Hexo 7 静态博客构建、布局修改与 Docker/Nginx 发布

#Hexo#Docker#Nginx#Git

静态站点维护分为三份：Hexo 源码保存文章、布局和配置；public/ 是可再生成产物；发布端目录只接收已生成文件。因此云端无需 Node 或 Hexo，构建问题与服务问题也可以分层处理。

更新、重建与回退

修改Markdown或主题后，先本地预览并重新构建，再发布新产物。Nginx始终读取同一Bind Mount，因此仅更新静态文件时不需要重建容器；只有镜像、端口、容器参数、Nginx配置或挂载关系变化时才需要重建。

后续接入与验收

先完成公网HTTP验证，再单独处理域名、备案、DNS和HTTPS。上线前检查：public/包含首页、文章、Atom和search；发布端版本或哈希正确；容器、挂载、端口、本机HTTP和公网HTTP均正常；上一版产物可以恢复。

发布前根据实际环境填写私密部署配置，并确认仓库权限、云网络规则和容器参数。凭证不要写入源码或生成文件。

dsh-our-free-model：把上游开放免费模型入口接进 DSH 的插件

2026年9月25日 · 项目 · 约 5 分钟阅读

更新于 2026年9月29日

把上游开放免费模型入口接进 DSH 的插件。

#开源项目#AI#Agent

本页目录

    dsh-our-free-model 由 Ebony-Vinyl 维护，做的事很直接：把 OpenCode Zen 与 Kilo AI 公共网关的免费模型通道接进 DeepSeek Harness，装好后不需要登录、注册或填写 API Key，模型就出现在输入框的选择器里。README 把它定位成客户端而不是模型服务方，所有响应都由上游生成。

    先别从 npm 装

    README 开头有一段醒目的警告：npm 上的同名包不是本仓库发布的，入口文件和客户端代码被改过，还多出仓库里从未有过的模块，装它拿不到本仓库的签名校验和应用内升级。可行路径有两个：下载仓库的 Release 发布包，或从本地源码目录安装：

    装完重启一次。桌面端（Electron）的 profile 只允许 App 自己管理，命令行写不进去，需要在 App 的插件管理器里操作。手工复制发布文件时还必须带上 adapter/、src/、locale/ 和 vendor/channel-pack/，只复制入口脚本会导致渠道加载失败。

    免费车道从哪里来

    基础免费通道走 OpenCode 的 Zen 网关，另一条是 Kilo AI 的公共网关免费池，均为直连，不经过插件自己的中转。模型集合、上下文长度和能力在每次刷新时向上游重新拉取，插件内不保存静态快照；网关明确拒绝路由的模型会从选择器移除，只在设置页保留拒因，被地区策略拦截的归入 region-limited 分组，选择器不会因此变空。

    模型清单与思考档位

    设置页的模型卡会列出可用性、是否支持视觉、上下文窗口、最长输出和实测首字延迟。思考强度分两种控制：带档位菜单的模型（如 DeepSeek V4.1 Flash、GLM 5.3 Flash）直接下发 reasoning_effort；没有档位菜单的模型走预算阶梯，Light、Balanced、Deep 分别对应 2,048、8,192 和模型上限个输出 token，不可关闭思考的模型三档整体翻倍。这些是 README 记录的机制，实际效果仍取决于上游是否遵守。

    本地网关与其他工具

    插件可以在本机开一个 OpenAI 兼容端口，提供 /v1/models、/v1/chat/completions、/v1/responses，也实现了 Anthropic 的 /v1/messages 与 token 计数接口。网关设置页会按实际端口和密钥生成 Claude Code、Codex、OpenAI SDK、Anthropic SDK 与 curl 的可复制配置。默认只监听回环地址，跨机器使用要显式开启“局域网访问”，并使用单独的中继密钥。

    用量看板把 Token 热力图、总量曲线、输出速度和首字延迟留在本机，不上传；工具输出压缩（RTK）则在请求发出前重写 tool_result，README 举的例子是 40 KB 的 git diff 能去掉约九成字节。路由功能把不同车道的模型串成 combo:<name> 虚拟模型，支持 fallback 与 round-robin，正文输出前失败才会切换，对调用方不可见。

    一个适合它的实验场景

    想比较几个模型对同一段代码的解释，又不想先给每个厂商开账号，可以在这台机器上装好插件，把本地网关地址填进另一个 CLI 或脚本，然后在设置页看每次请求的耗时、首字延迟和 token 消耗。实验结束后关掉网关即可，不需要清理云端资源。

    与自备 Key 的聚合客户端对比

    OpenRouter 一类聚合服务要求注册、充值并管理 Key，换来的是明确的账单、配额和账号体系；dsh-our-free-model 把“免账号”放在第一位，代价是可用性完全由上游决定。它也能接入自备 Key 的聚合渠道，README 记录内置 76 家提供商，Key 只写入本机 0600 的 settings.json。两条路线可以并存，敏感任务仍应走自己付费、条款明确的那条。

    限制与风险

    免费额度由上游单方面提供，可能限流、收费或下线，地区策略会返回 403，超量会返回 429。Kilo 免费池的模型卡明确写着 prompt 可能被上游记录并用于改进服务，README 也提醒不要发送密码、密钥、个人信息或商业机密。插件处于 beta，上游条款由使用者自己遵守。本文按官方 README 与仓库元数据整理，未在本机完整实测。

    适合谁

    适合想低成本试模型、做本地实验、或给内部脚本临时找一个 OpenAI 兼容端点的开发者。需要 SLA、审计、稳定上下文和数据处理协议的团队，应直接购买正式 API，不要把免费车道接进生产。

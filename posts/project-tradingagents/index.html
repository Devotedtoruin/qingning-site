TradingAgents：多智能体金融研究与交易框架

2026年9月6日 · 项目 · 约 5 分钟阅读

更新于 2026年9月10日

多智能体金融研究与交易框架。

#开源项目#AI#Agent

本页目录

    TradingAgents 是 Tauric Research 开源的多智能体金融研究框架，论文编号 arXiv:2412.20138，代码以 Apache-2.0 发布。目标不是替人下单，而是把一家交易公司的分工压缩成一次可重复的分析流程：分析师各自研究，研究员正反辩论，交易员提出方案，风控与组合经理决定是否放行。README 反复注明它只用于研究，不构成投资建议。

    角色如何分工

    基本面分析师读财报与指标，情绪分析师汇总新闻、StockTwits 和 Reddit 的立场，新闻分析师跟踪宏观事件，技术分析师看 MACD、RSI 等价格信号。选中的分析师并行工作，报告齐了才进入研究辩论；看多与看空研究员互相挑错，交易员综合两边意见给出方向与仓位，风控团队评估波动、流动性等风险，最后由组合经理批准或拒绝。实现基于 LangGraph，支持 OpenAI、Anthropic、Google、DeepSeek、Qwen、GLM、MiniMax、OpenRouter、Ollama、Azure OpenAI、AWS Bedrock 以及任意 OpenAI 兼容端点。

    从命令行到回测

    每次运行的结果、报告、记忆日志和缓存默认写入 tradingagents_data 卷；设置 TRADINGAGENTS_DATA_DIR 可以改到宿主机目录。没有 API Key 时可以在 CLI 的供应商菜单选 Subscription，或设置 llm_provider: "chatgpt"，用 tradingagents login chatgpt 登录 ChatGPT Plus/Pro；登录信息保存在 ~/.tradingagents/chatgpt-auth.json，tradingagents logout chatgpt 可撤销，运行会占用套餐额度。回测按标的与日期网格重跑同一套流程，并按区域基准计算已实现 alpha：

    --checkpoint 会在每个节点后保存 LangGraph 状态，崩溃或中断后可从上次成功的步骤继续。美股财报取自 SEC EDGAR，并按披露日期还原历史口径；其他市场走 Yahoo Finance，历史日期下的财报与内部交易会被标记为不可用，而不是假装当时已知。也可以把自己的持仓作为 PortfolioContext 传入，让交易员、风控和组合经理围绕真实仓位工作。

    一个典型场景

    研究者想在财报前比较一只股票的多空理由：选定 NVDA 和某个历史日期，让四位分析师并行出报告，再读研究员的辩论记录，观察交易员如何把结论落成方向。随后用同一日期区间跑回测，检查这类决策在持有窗口结束后的表现。如果只关心短期消息面，可以只选新闻与情绪分析师，减少不必要的调用。整个过程留下报告、决策日志和回测摘要，便于复盘，而不是只看一次聊天的结论。分析结果和回测评分要分开看：前者是当时的推理记录，后者才涉及持有期结束后的收益。

    与单 Agent 选股脚本的差别

    单 Agent 脚本通常一次提示就给出买卖结论，缺少角色冲突和风控否决；OpenBB 这类工具更偏数据终端，负责取数与研究入口。TradingAgents 的重点在流程编排和辩论，数据仍来自外部供应商。两者可以并用：用数据终端核对数字，再用多 Agent 流程做情景分析，最后由人判断是否值得继续研究。

    限制与风险

    LLM 采样本身不确定，同一标的和日期跑两次结果可能不同；新闻与社交数据随时间变化，历史回测也只能固定价格窗口，不能完全还原“当时能看到什么”。回测收益不保证复现 README 或论文中的任何数字，模型、温度、日期区间和数据质量都会改变结果。框架最后把订单送到模拟交易所，不连接真实券商，不能当作实盘交易系统。按官方 README 整理，未在本机完整实测。适合研究多 Agent 协作、做策略回测与情景分析的开发者；想直接获得投资建议或自动实盘的人不适合。

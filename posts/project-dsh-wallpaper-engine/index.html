dsh-wallpaper-engine：把 Wallpaper Engine 壁纸接进 DSH 的插件

2026年9月21日 · 项目 · 约 5 分钟阅读

更新于 2026年9月25日

把 Wallpaper Engine 壁纸接进 DSH 的插件。

#AI#开源项目#Agent

本页目录

    elysia395 的 dsh-wallpaper-engine 把本机 Wallpaper Engine 的场景、网页和视频壁纸搬进 DSH 的网页界面，再叠加液态玻璃、字体、吉祥物和可分享的外观预设。插件不向模型注册工具，也不注入提示文本，README 明确说不增加 token 开销——它改的是界面，不是 agent 能力。

    三类壁纸，以及一类不支持

    Scene 壁纸由插件内置的 WebWallGL 实时渲染，支持粒子、puppet 骨骼、SceneScript、鼠标交互和音频反应，不要求 Wallpaper Engine 在后台运行；渲染失败会逐级降级到内嵌 MP4 或静态帧。Web 壁纸通过网页挂载、WE API 注入和沙箱隔离运行，效果取决于网页本身和浏览器能力。Video 壁纸直接交给浏览器播放，配合转码、帧率上限和暂停控制。

    Application 类型需要启动第三方可执行程序，插件明确不支持，也不会把它放进壁纸库或轮播候选。自定义 JPG、PNG、MP4 可以上传，文件保存在本机。

    外观设置不止换图

    设置页分为壁纸库、外观、播放、系统、扩展、关于六块。外观里能调玻璃效果的配色、透明度、雾化和边框，也能按颜色角色与排版角色细调字体；扩展里有会话头像、点击与拖尾、3D 视差，不需要的可以逐项关闭。吉祥物转盘内置十只立绘，也支持导入自己的素材；3D 圆环切换时会要求确认是否清除自定义立绘。

    壁纸库支持按内容分级和类型筛选、批量隐藏与恢复、自动轮播。轮播至少需要两张可播放壁纸，下一张准备完成后再交接，失败候选自动跳过；系统开启“减少动态效果”时会用硬切。暂停或清除当前壁纸不会删除源文件。

    一个桌面端的使用场景

    长时间在 DSH 里读代码、跑任务时，把壁纸换成低动态的场景，开启遮挡暂停，窗口被挡住时停止解码和渲染；写文档时换成静态图，减少 GPU 占用；听歌时打开音频反应，让壁纸随系统输出回环的频谱变化。音乐联动读取的是输出回环而不是麦克风，Now Playing 能显示歌名、歌手、专辑和封面；在线歌词默认关闭，开启后才会在本地歌词缺失时向 LRCLIB 查询。

    与 Wallpaper Engine 本体、浏览器主题的差别

    Wallpaper Engine 管的是桌面壁纸，换不到网页界面里；浏览器主题通常只改配色和背景图，不处理 Scene 或 Web 壁纸。dsh-wallpaper-engine 把渲染搬进 DSH 页面，因此能同时改壁纸、玻璃、字体和吉祥物。若只想让桌面动起来，继续用 Wallpaper Engine 本体即可，不必多装一层插件。

    限制与资源占用

    场景渲染依赖浏览器 WebGL 和显卡驱动，复杂工坊项目可能存在兼容差异，README 也不保证每张壁纸与 Wallpaper Engine 本体完全一致。macOS 没有 Wallpaper Engine 官方客户端，只能上传图片、视频，或把自定义壁纸目录指向已有的 WE 项目。ffmpeg 不可获取时转码和帧率上限失效，视频仍可按原片播放。插件会按需下载运行时并查询仓库信息，开启在线歌词还会访问外部服务，所以不是“完全离线”插件。设置保存在宿主端 ~/.dsh-wallpaper-engine/config.json，可用 DSH_WE_DATA_DIR 等环境变量改位置。本文按官方 README 与仓库元数据整理，未在本机完整实测。

    适合谁

    适合在桌面端长时间使用 DSH、愿意为界面观感付出一点 GPU 和配置成本的人。移动端、低配机器，或者只关心 agent 输出速度的用户，收益有限，默认主题反而更稳。

OpenCut：免费、无水印、本地渲染的开源剪映替代

2026年9月8日 · 项目 · 约 5 分钟阅读

更新于 2026年9月12日

免费、无水印、本地渲染的开源剪映替代。

#开源项目#视频

本页目录

    OpenCut 是 OpenCut-app 组织维护的开源视频编辑器，定位是 CapCut、剪映的免费替代，目标是覆盖浏览器、桌面和移动端。项目用 TypeScript 编写，MIT 许可，官网是 opencut.app。它想解决的是剪辑工具的两类摩擦：基础功能被订阅墙挡住，以及素材必须上传到厂商云端。本文按官方 README 整理，未在本机完整实测；项目正在重写，具体可用版本以下载时的仓库说明为准。

    仓库现在讲的是“重写版”

    README 开头就说明项目正在从底层重写。当前 GitHub 主仓库描述的是未来架构：Editor API、插件优先架构、用 Rust 核心让桌面、移动和浏览器共用一套代码、给 AI Agent 的 MCP server、无头批量渲染，以及编辑器内的脚本标签页。

    README 同时给出当前可用的路径：旧版本在 opencut-app/opencut-classic，opencut.app 仍运行经典版，重写版放在 new.opencut.app，准备好后才接管。而经典版仓库的 README 又标注该项目已归档、不再维护。两条信息放在一起，结论很清楚：经典版是目前能用的版本，但不会再有新功能；重写版代表方向，尚未成为稳定产品。

    编辑器能力

    按经典版 README 的说明，项目的出发点是隐私、免费功能和简单易用：视频留在自己的设备上，不强制上传；CapCut 逐步收费的基础能力，OpenCut 保持免费；界面尽量降低学习成本。仓库的开发重点列的是时间线、项目管理、性能和界面改进，预览面板的字体、贴纸、特效和导出模块正在换成新的二进制渲染方案。

    这意味着它适合做常规的剪切、拼接、预览和导出，而不是复杂的合成。浏览器端是当前的主入口，桌面端在经典版仓库里标注为开发中，不能假设下载即用。

    一个典型场景

    出差途中用笔记本剪一条三分钟的产品演示：素材放在本地磁盘，浏览器打开编辑器，粗剪、拼接、调整顺序，导出 MP4 后直接发给同事。整个过程不需要把原片传到网盘，也不用为了去水印买订阅；导出文件留在本地，后续是否继续编辑取决于你使用的版本和项目存储方式。

    和同类工具的差别

    与剪映、CapCut 相比，OpenCut 的核心卖点是开源、免费和本地处理，代价是功能完整度和稳定性取决于版本。与 Shotcut、Kdenlive 这类桌面 NLE 相比，它把界面放在浏览器里，跨设备和协作更自然，但专业多轨、调色台和团队审片流程还不是它的强项。重写完成后计划提供 MCP 和 headless 渲染，这两项会把它和传统剪辑软件区分得更明显，但目前仍属于路线图。

    限制

    最现实的风险是版本分裂：主仓库是重写中的代码，经典版才是可用产品，两者的功能、issue 和文档不能混着看，而经典版已经归档。README 也说明重写会带来 Editor API 和插件架构的破坏性变化，现在写的插件不一定能平滑迁移。在线协作、移动端完整度和大型项目性能，需要按你下载的具体版本实测；导出编码和浏览器兼容性也要自己验证。

    适合谁

    适合想要免费、无水印、素材不外传的短视频创作者和小团队，以及愿意跟进开源编辑器架构的开发者。需要成熟多轨剪辑、团队审片和稳定交付的后期团队，应继续使用成熟 NLE。

caveman：压缩日志、表格和测试输出的 token 优化 Skill

2026年9月15日 · 项目 · 约 4 分钟阅读

更新于 2026年9月19日

压缩日志、表格和测试输出的 token 优化 Skill。

#AI#开源项目#Agent

本页目录

    caveman 由 JuliusBrussee 发起，README 把它写成“少说、少读，代码保持原样”的 token 优化工具。它既可以作为 Agent Skill 安装，也能作为 CLI 或代理接管本机的 coding agent。项目从一句玩笑长成一套多层工具，但核心一直没变：别让模型把上下文浪费在重复解释和噪声日志上。

    三块能力，不是一句“请简洁”

    第一块是输出风格。/caveman、/ultracave、/megacave 用不同强度要求回答先给动作和原因，一句只讲一件事；代码、命令、路径和报错必须逐字保留，否定词和数字不能丢。README 特别说明它不改写用户提示词，因为已有研究认为把用户输入也“压缩”反而会让回答变差。

    第二块是输入压缩。日志、JSON、CSV、YAML 和测试输出在进入模型前先被压缩成保留关键信号的版本，原始文件仍留在磁盘，Agent 需要时可以回读。caveman shrink -- pnpm test 可以直接把一条命令的噪声输出变短，/caveman-compress <file> 则用于压缩 CLAUDE.md 这类记忆文件，并保留备份。

    第三块是代码模式里的 Blocks。Agent 经常把同一段脚本写一遍、跑一遍、丢掉，下次重写；Blocks 把 test-summary、json-peek、first-error 等常用脚本留在仓库里，下次直接复用。caveman-blocks scan 可以看本机最近重复写了什么，caveman-blocks init 把规则写进项目的 AGENTS.md。这部分 README 标注为预发布，且目前只支持 Python。

    安装和几个常用命令

    安装器会找到本机的 agent 和登录方式，确认后写入配置，要求 Node.js 22.13 以上。只想用回答风格、不要代理时，可以只装 Skill：

    常用检查命令是 caveman status 看哪些能力开启，caveman doctor 逐条报问题，caveman learn 分析 token 花在哪里。caveman off browse 这类命令可以单独关掉某一层。它声称支持 30 多个 agent，具体名单以仓库的 INSTALL.md 为准。

    长任务排障时最能看出差别

    一次前端构建失败，终端里几千行依赖告警、重复堆栈和最终一条类型错误。直接把这些内容粘给 Agent，上下文很快被填满，模型还可能盯着无关告警解释。用 caveman 的输入压缩先过滤噪声，再让它按错误发生的文件和时间线排查；需要逐字核对时，再打开原始日志。输出层则要求它先给下一步动作，省掉“让我来分析一下”之类的铺垫。压缩前后都应保留原始文件路径和完整命令，方便随时回查。

    和 tail、jq 与通用简洁提示的对比

    tail 只保留末尾，适合看最后一条错误，但会丢掉前面的上下文；jq 能结构化筛选 JSON，却要自己写查询；通用的“请简洁”提示词能减少客套，但管不到输入侧。caveman 把输出、输入和脚本复用拆开，适合长会话。README 自己也承认，“请简洁”已经是很强的基线：在某些测试里 /caveman 的中位数只比它再省 3%，/ultracave 才拉开更大差距。

    限制和风险

    压缩是有损的。审计日志、法律文本、需要逐字比对的合同，以及必须保留全部堆栈的故障，都不适合交给自动压缩。README 还写明 HTML 目前没有压缩器，某些文件类型可能没有收益；按请求计费的场景，回答变短也未必省钱。CLI 默认发送使用统计，可用 caveman telemetry off 或 DO_NOT_TRACK=1 关闭。

    性能数字来自项目自己的对照测试，换模型、换任务和换版本都可能不同，不应把 README 的百分比当成保证。最适合经常让 Agent 读构建日志、测试报告和长表格的开发者；如果你需要完整保留推理过程，或者工作流要求每字可审计，应该绕开这类压缩。

    入口

    仓库：https://github.com/JuliusBrussee/caveman 。官方文档：https://docs.caveman.so/caveman 。许可证以仓库为准，README 当前标注 Apache-2.0。本文按官方 README、安装说明和仓库元数据整理，未在本机完整实测。

Piik：免费 P2P 屏幕共享工具

2026年9月22日 · 项目 · 约 4 分钟阅读

更新于 2026年9月26日

免费 P2P 屏幕共享工具。

#开源项目#效率工具

本页目录

    Piik 是 TNTcraftHIM 维护的开源屏幕共享工具，MIT 许可，定位不是网络会议，而是给朋友开一间私人放映室：一个主持人共享屏幕、窗口、浏览器标签或摄像头，最多 20 位观众直接用浏览器加入，不用安装客户端。

    一间只给朋友的放映室

    想一起看游戏、看电影、看画，常见的做法是开会议软件、建群、发会议号，或者把内容传到直播平台。前者功能很多但账号和权限绕，后者会把内容公开出去。Piik 把流程压成一条邀请链接：主持人选好要分享的画面，复制邀请，朋友在桌面或手机浏览器里打开就能看。

    房间支持邀请码和可选密码，还带语音、文字消息、表情和屏幕上的聊天。主持人可以只共享一个应用窗口，避免把整个桌面和通知一起播出去。

    点对点优先，服务器兜底

    媒体流尽量在参与者之间直连，减少中转延迟和服务器带宽；需要时可以在自己的服务器上启用 SFU 转发作为回退。这个设计对小范围观影、联机游戏很合适，但网络条件会直接影响体验。

    分享源可以是 Piik App，也可以是已有的 Piik 站点。可选范围取决于平台，音频能不能一起共享也要看系统和浏览器。远程控制需要主持人批准，朋友接管键盘鼠标后，主持人随时可以收回。播放控制、画中画、明暗主题和连接拓扑视图，都是围绕“看得清、知道谁连上了”做的。

    自建站点与本地试用

    Piik Server 是一个自带 Web 界面的独立二进制，房间数据存在 SQLite 里。Linux x64、Linux ARM64 和 Windows x64 都有对应的运行包，解压后直接启动：

    启动后打开 http://localhost:8787 就能看到本地站点。对外提供服务还要配置域名、HTTPS 反向代理和 STUN 地址；容器部署可以用官方 Docker Compose 方案。以下内容按官方 README 整理，未在本机完整实测。

    浏览器采集要求 HTTPS 或 localhost。P2P 需要参与者之间有可用的 UDP 连接，校园网、虚拟局域网或严格 NAT 环境可能连不上，官方文档给了网络检查和改用中继的说明。

    一次周末观影

    主持人下载 Piik App，选择正在播放的电影窗口和系统音频，复制邀请链接发到群里。朋友不用装软件，点开链接后按一下播放。有人网络不稳时，主持人切到自建服务器的转发模式；看完后关掉房间即可。整个过程不需要把影片上传到第三方平台，也不依赖会议软件的日程和账号体系。

    与会议软件的分工

    腾讯会议、Zoom、Discord 这类工具覆盖会议、录制、权限管理和大型活动，Piik 只做“一个主持人和一小群观众”的实时共享。浏览器加入和可自建是它的优势，代价是功能面窄：README 没有把录制、大型会议管理或复杂权限列为主打能力。和直播平台相比，Piik 不面向公开推流和观众增长，房间是私密的。

    网络和规模是两道坎

    一个房间最多 20 位观众，超过这个规模就不该继续加人。P2P 在双方网络都正常时最省资源，但跨运营商、校园网或公司网络常会遇到 UDP 不通，此时要么排查网络，要么自建转发。浏览器采集必须处于安全上下文，HTTP 页面下的屏幕共享会被浏览器拒绝。

    自建站点还要维护域名、证书、反向代理和 SQLite 数据，房间不多时这些工作可能比使用现成会议软件更重。

    适合的群体

    适合和朋友定期看电影、看游戏、远程展示作品的小群体，也适合愿意自建服务、在意画面不经第三方平台的用户。需要录制、回放、几百人观看或企业权限管理的人，应该选会议或直播系统。

paperless-ngx：文档扫描、OCR、索引和归档的自托管系统

2026年9月4日 · 项目 · 约 4 分钟阅读

更新于 2026年9月8日

文档扫描、OCR、索引和归档的自托管系统。

#开源项目#效率工具

本页目录

    paperless-ngx 是一套社区维护的文档管理系统，目标很直接：把纸质单据变成可搜索的在线档案。项目由 paperless-ngx 团队共同维护，是 Paperless 和 Paperless-ng 的官方后继版本，采用 GPL-3.0 许可，后端以 Python 和 Django 为主。

    从“存下来”到“找得到”

    发票、合同、保修卡、说明书，扫描或拍照只能解决保存问题。几年后要找回其中一张，靠文件名和文件夹往往不够。paperless-ngx 在文档入库时做 OCR，把图片里的文字变成可检索内容，再连同索引和归档信息一起保存。README 用 scan、index、archive 三个动作概括这套流程，指向的正是“以后还能找到”。

    文档入库之后

    扫描件进入系统后先转成可检索文本，搜索依据是正文而不只是文件名。文档集中保存在自己的服务器上，通过浏览器浏览、筛选和检索，不必在多个网盘目录之间来回翻。官方还提供了一个演示站，登录名和密码都是 demo，可以先看数据怎么组织、界面是否顺手，再决定要不要自建。演示内容会定期重置，README 明确提醒不要上传机密信息。

    从 Paperless-ng 迁移的成本相对低。README 的说法是直接换用新的 Docker 镜像，具体迁移步骤仍要对照文档执行，尤其是数据库版本和卷路径。

    README 也提醒，扫描仪处理的往往是社保号、税务记录、发票这类敏感材料。部署前先决定数据盘放在哪、谁能登录、备份保留多久，比事后补权限更省事。文档量上来以后，索引和原件会一起增长，存储规划要留出余量。

    一个家庭归档场景

    把每年的发票、房屋合同和家电说明书分批扫描进系统，等 OCR 完成后再统一检查一遍关键字段。以后报修或报销时，用正文里的商户名、金额或型号搜索，比翻手机相册快得多。这个场景真正花时间的是第一次整理：归档规则、命名习惯和备份策略定得越早，后面越不需要返工。

    和网盘、Paperless-ng 的区别

    只把扫描件放进网盘，得到的是“能存能同步”，但没有文档级 OCR 索引，搜索通常只覆盖文件名。Paperless-ng 用户迁移成本较低，但旧项目已不再演进，修复和新功能集中在 paperless-ngx。与商业扫描归档服务相比，自托管把数据留在自己的机器上，代价是数据库、存储、备份和升级都要自己负责。

    明文存储与维护边界

    README 的 Important Note 写得很重：系统以明文保存文档，不做加密，不应运行在不受信任的主机上；最安全的做法是放在家里的本地服务器，并准备好备份。这意味着主机权限、磁盘加密、备份介质和访问控制都得自己补齐。OCR 也会出错，合同金额、日期这类关键字段不能只依赖搜索命中，仍需人工核对。

    谁适合长期用

    家里或小团队有大量纸质资料、愿意维护一台 Docker 主机并定期备份的人，比较适合。只想把文件同步到手机、不打算维护服务的人，用网盘更省事。

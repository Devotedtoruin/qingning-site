    静态博客前端（二）：外观切换、分层背景与可访问性回退

    以本站的玻璃、纸页、夜色三种外观为例，解释背景分层、透明度、枚举校验、本地偏好与实色回退。

    #CSS#可访问性#渐进增强

    背景照片可以提供气氛，却不能决定正文是否看得清。毛玻璃界面的难点不在写出 blur()，而在背景明暗、浏览器能力和用户偏好变化后，内容仍有稳定的阅读入口。

    本文依据本站主题 CSS、appearance.js 与页头控件解释实现。源码核对日期为 2026-10-13；这里说明的是可确认的设置与回退逻辑，不提供未实测的对比度、GPU 开销、兼容性评分或合规结论。

    先把外观、背景和透明度分成三个选择

    从页头的“外观”打开面板，可以分别选择外观、背景和面板透明度。

    设置 可选值 职责
    外观 玻璃 glass、纸页 paper、夜色 night 控制面板与前景的视觉变量
    背景 林间晨光 forest、暖色渐变 gradient、湖山插画 illustration 选择背景来源，不改文章内容
    面板透明度 0–45%，默认 18% 调整面板底色的 alpha，不让文字一起变淡

    玻璃使用浅色半透明面板；纸页将面板底色改为实色；夜色使用深色表面、浅色文字和相应的代码 token 配色，并设置 color-scheme: dark。这不是只把 body 背景涂黑：链接、日期、代码高亮、按钮选中态也要随语义变量变化。

    纸页下透明度偏好仍保留，切回玻璃或夜色再生效。因此滑块的值与当前纸页的实色表现并不矛盾，帮助文字应解释这一点。背景与外观相互独立，切换背景不应顺便重置透明度。

    用户可以用 Tab 进入按钮与滑块，用原生 range 的方向键调整；选中按钮用 aria-pressed 表达状态。按 Escape 收起面板并将焦点返回 summary。“恢复默认”恢复玻璃、林间晨光、18%，移除三项保存值，并重新遵循系统减少透明度偏好。

    背景和内容必须处于不同绘制层

    本站以 body::before 承载背景，用 pointer-events: none 避免装饰层抢走点击。body 建立隔离上下文，背景留在内容后方；正文、列表和目录使用带 alpha 的底色，文字仍在前景。

    CSS 的 --background-image 选择照片、渐变或插画，--backdrop-veil 提供遮罩。滑块改变的是 --panel-alpha，不改变照片、不改变遮罩，更不改变文字和正文图片。夜色另外使用较深遮罩，与透明度选择是两个维度。

    给整个文章容器设 opacity: 0.82 会把文字、按钮、图片一起参与透明合成，还会创建新的堆叠上下文。想调整纸面，应该改底色 alpha，而不是整块元素的 opacity。以下是教学示例，不是本站完整补丁：

    一个内容组只保留一个主要玻璃面

    主题把首页主列、侧栏区块、文章和目录作为主要面板；列表行使用透明底与分隔线。若父容器和每张卡片都各叠一层半透明底色，合成结果会越来越实，边框与阴影也会重复。

    滑块“似乎没效果”时，先在开发者工具检查内层是否仍有不透明背景，再检查后面的选择器是否覆盖变量。代码块、搜索、外观面板和播放器控件保留更稳定的底色是有意选择：操作区域不应为了背景效果牺牲辨认能力。

    CSS 变量是维护边界，不是免验收凭证。切换夜色后，如果复制按钮仍沿用旧浅底文字，说明某个局部组件绕过了语义变量；继续增加全局选择器往往只能遮住问题。

    输入校验应先于应用和保存

    透明度 18% 对应 alpha 0.82，0% 对应实色。当前代码只接受可安全表示的整数串，再夹取到 0–45；空值、损坏值或非整数回默认 18%。因此超范围整数与任意坏字符串有不同处理，不应统称为“所有非法值都归零”。

    设置仅存本机 localStorage：qingning.panelTransparency、qingning.appearance 和 qingning.background，不保存浏览记录或身份。读取异常时使用默认值；写入被拒绝时本页调整仍可用，只是不保证下次保留。storage 事件同样经过校验，其他标签页清空设置时恢复默认。

    外观脚本在 head 阶段读取设置并应用根属性，DOM 就绪后再同步控件，目的在于减少首次绘制之后的突然切换。这是实现意图，不等于已测得零闪烁。排查时可以分别检查首次加载、存储拒绝、跨标签页切换和 PJAX 之后的控件值。

    用户偏好和浏览器能力不是同一件事

    降低透明度、降低动画和强制颜色分别解决不同需求。

    1. 未主动调整滑块时，系统 prefers-reduced-transparency: reduce 使面板使用实色并取消面板背景模糊。主动移动滑块后，data-panel-preference="custom" 表示自定义选择；恢复默认清除此意图。
    2. 不支持背景滤镜时，@supports not 使用实色底色；即使保存了自定义透明度，也不能让能力回退失效。
    3. forced-colors: active 使用 Canvas、CanvasText、LinkText 等系统颜色，移除背景照片、模糊和阴影。选中按钮另有边框反馈，不只依靠颜色差异。
    4. prefers-reduced-motion 针对平滑滚动和装饰动画，不应隐式停止用户主动播放的音频。

    检查不能停在“找到了媒体查询”。CSS 存在历史覆盖规则，必须看最终级联、选择器优先级和对应模式下的计算样式。减少透明度媒体查询并非所有浏览器都支持，因此 0% 透明度和纸页外观仍是有用的手动入口。

    对比度必须针对合成后的背景

    带 alpha 的面板没有单一最终底色。照片、遮罩、模糊和纸面合成后，文字背后的颜色才是实际背景。仅用 CSS 中纸色与文字色计算，不能证明所有照片区域都通过。

    普通文本常用的 WCAG 最低对比度要求是 4.5:1，大文本是 3:1；大文本有字号与字重条件，不能因为类名叫 title 就直接按 3:1 验收。按钮边界、焦点轮廓与状态还需要检查非文本对比度和可辨性。

    可以按默认、0%、45% 三组透明度，逐一观察正文、弱化日期、标签、链接和焦点，再覆盖亮背景与暗背景。若最高透明度使弱文字难读，优先调整范围、底色或文字色，不要用浓阴影给每个字描边。模糊能减少细节，不能保证亮度安全。

    性能与可用性分开检查

    大面积固定背景、滤镜和相邻面板可能增加绘制与合成成本，但不能从 blur(14px) 推导某台手机的帧率。应记录浏览器、设备、页面长度与测试条件，再观察首次渲染、长文滚动、搜索、拖动滑块和切页。

    功能检查则要确认：三个外观都能阅读代码与表格；背景加载失败不阻挡正文；纸页解释透明度保留；拒绝存储不让按钮失效；重置与跨标签页更新同步；窄屏面板不超出视口；键盘收起后焦点可见。

    本文没有执行对比度测量或设备性能测试，以上是检查方法，不是结果。实现依据为主题 source/css/style.css、source/js/appearance.js 与 layout/_partial/header.ejs。延伸参考：MDN：backdrop-filter、MDN：opacity、W3C：Contrast Minimum。

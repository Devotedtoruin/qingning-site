huashu-art-motion：35 种艺术风格、9 种解说语法的代码动画 Skill

2026年10月6日 · 项目 · 约 5 分钟阅读

更新于 2026年10月10日

35 种艺术风格、9 种解说语法的代码动画 Skill。

#开源项目#AI#视频

本页目录

    huashu-art-motion 是花叔 Huashu 的动画 Skill，目标不是让 Agent 套一个视频模板，而是用代码把画面画出来、让它动起来。仓库把艺术风格、解说语法、渲染引擎、拆解脚本和验收工具打包在一起，交给 Claude Code、Codex 等 Agent 按需读取。

    两套积木：风格与解说

    风格库覆盖洞穴壁画、埃及壁画、梵高、克里姆特、包豪斯、8-bit、蒸汽波、新海诚等方向。README 的样片总览是 35 格，后来又补了第 36 种 Rick and Morty 风格，作为独立 SVG 示例，不在这 35 格里。每张风格配方卡记录参数、母题动作、签名转场和当前短板，场景代码放在 scripts/engine/scenes/。

    解说语法是另一套积木，包含 Kurzgesagt、Vox、白板、storytime、动态文字、3Blue1Brown、发布会 UI 和财经图表等 9 种。前 8 种有示范片、参数化片段和示例 spec，第 9 种“讲解员式财经科普”提供语法卡和整片代码快照，但需要自备角色素材。风格决定画面长什么样，语法决定信息怎么被讲出来，两者可以组合。

    用代码交付，而不是时间线工程

    核心引擎在 scripts/engine/，包含 17 个绘画与动画库、转场、场景和示范片。每一段动画可以由 JSON spec 驱动，输出横屏、竖屏或透明底，时长精确到帧。依赖是 uv、ffmpeg 和 Playwright Chromium；第一次运行要安装浏览器：

    第一条渲染命令只出一张静帧，适合检查风格和构图；第二条才把整段 spec 渲染成视频。人物镜头由生图模型出帧，代码负责合成、换帧和材质；配乐可以用 BPM 网格和代码合成，不强制依赖外部音源。

    交付前的数字验收

    仓库不只管生成，还管验收。qa.py 会量稳定性、效率、动感、流畅度和文字出框线索，再让一个没参与制作的 Agent 只看成片挑问题。film_gate.py 检查“翻页式 PPT 感”和中段空画面，deliver.py 把门禁、复制成片和写交付说明串成一条命令。render.py --audit 和 clip_lint.py 则检查出界、叠字和字号过小。README 把这些定义为流程，不代表任何一条片子都能自动过关。

    一条 60 秒解说段的做法

    手上有一段口播，想把中间的数据关系做成动画。先让 Agent 按口播选语法，财经图表适合“先轴、后数据、只标一件事”，白板适合边讲边画关系；再准备一份 JSON spec，写清镜头、时长、数据点和配色。先渲染静帧确认版式，再出整段 MP4。需要人物时，用生图模型生成角色帧，代码只负责让它在画面里移动和换表情。

    和 AE、Remotion 的差别

    After Effects 是时间线工具，适合逐帧合成和精细调参；Remotion 用 React 写视频，适合工程团队把视频接进代码库；huashu-art-motion 更靠前一步，把风格配方、解说语法和 Agent 工作流一起封装。它没有可视时间线，修改靠 spec 和代码；复杂粒子、3D 和实拍合成仍要交给专业工具。

    限制与许可

    运行门槛不低：uv、ffmpeg、Playwright Chromium 缺一不可，第一次装浏览器也要时间。Skill 内容以中文为主，复杂制作仍要人看片、调节奏。部分完整口播示例是代码快照，并不等于开箱即用的可渲染工程；第 9 种语法也要自备角色素材。许可证是 MIT，但有几个例外：字体沿用各自的 OFL，笔顺衍生数据沿用 Arphic Public License，花叔的卡通形象和角色帧只用于本 Skill 示范，Clawd 同人片段不随 MIT 授权。商用前要逐项核对。

    适合做解说视频、数据演示、艺术短片和视觉叙事的内容创作者，也适合想把动画流程代码化的开发者。需要真人拍摄、复杂合成或严格交付周期时，传统制作管线更稳。

AIHOT：自己找热点、自己写日报的行业资讯站框架

2026年9月28日 · 项目 · 约 6 分钟阅读

更新于 2026年10月2日

自己找热点、自己写日报的行业资讯站框架。

#开源项目#AI#效率工具

本页目录

    AIHOT 是数字生命卡兹克开源的行业热点站框架，MIT 许可，也是 aihot.news 线上站点使用的引擎。作者自述是设计师出身，这套代码由他和 AI 一起重写。仓库把信源接入、模型筛选、写作、聚簇、热度和日报的整套流程都放了出来，换掉信源和精选标准，就能做成另一个行业的热点站。

    把行业热点站做成一条流水线

    垂直资讯站真正难的不是搭页面，而是每天从大量来源里挑出值得看的内容，去掉重复，写成可读的摘要，再按热度排出来。AIHOT 把这套工作拆成六步：采集、预筛、两次评分、写作、聚簇、热点与成刊。每一步的提示词都在仓库里，入选门槛也公开，想改标准不必动代码。

    六类信源与两次评分

    信源支持 RSS、网页列表、JSON 接口、X 账号、微信公众号，以及自己脚本推送的内容。来源分三级：官方一手、官方账号与准官方、媒体与个人，各级使用不同的入选门槛，抓取频率会按产出自动调整。

    一条资料进来先判重、预筛，可能重要的再按同一份标准独立打两次分，过了门槛且不是已有新闻的重复才进入精选。写作阶段生成中文标题、答案先行的摘要和推荐理由，外文内容可以全文翻译；分类、标签和新闻事实单独抽取，避免模型把原文没提到的公司写进标题。

    聚簇解决“同一件事被十家媒体转发”的问题：先用向量或文字重合度找候选，再让模型判断是同一事件、后续进展还是两件事，拿不准的合并后再复核。热度按事件算，不按文章算；48 小时内每个独立来源只算一次，24 小时减半。日报默认每天 08:00 出刊，周报和月报从日报汇编，时间可以在 site/site.ts 的 EDITION_TIMES 里改。

    本地跑起来

    需要 Docker、Node.js 24，以及一个 OpenAI 兼容的模型 API Key。默认配置按 DeepSeek 写，换千问、智谱等供应商时改 .env 里的 LLM_BASE_URL、LLM_MODEL 和 LLM_EXTRA_JSON。

    打开 http://localhost:3000，后台在 /admin，管理员密码在 .env 的 ADMIN_PASSWORD 里。首次导入的资料大约半小时处理完。以上命令按官方 README 整理，未在本机完整实测；中国大陆网络、域名和 HTTPS 另有部署文档。

    改成自己的行业

    仓库带了 18 个公开的海外 AI 资讯源作示范，真正的信源要换成自己行业的。改动集中在两个目录：site/site.ts 管站名、行业词、出刊时间和首页文案；industry/ 管分类、主题、信源、提示词和入选门槛。评分标准在 industry/prompts/selection-score.md，最值得花时间校准；README 建议用一两百条自己标注的资料跑 scripts/eval-selection.ts，看选得准不准再回去改。

    不想逐文件读，也可以把仓库交给 Claude Code 或 Codex，让它按 AGENTS.md 和 docs/customize.md 执行改造，再跑类型检查、测试和 smoke 脚本。

    一个垂直媒体的日报场景

    一家做劳动法的机构可以只盯法规更新、法院公告和几家行业媒体，把“哪些案子会影响用工”写进评分标准。每天早上编辑打开日报，先看聚簇后的事件，再抽查几篇摘要的准确性；需要深度解读的内容仍由人写。站点同时提供 RSS、公开 API、MCP 和 llms.txt，读者用浏览器或 Agent 都能取到同一份内容。

    和 RSS 阅读器、通用 AI 写作工具的区别

    FreshRSS 一类阅读器擅长聚合，但不做两次评分、事件归并和成刊；通用 AI 写作工具能生成摘要，却没有稳定的信源管道、去重和发布节奏。AIHOT 更接近一条编辑部流水线：采集、筛选、写作、编排都在一个仓库里。它仍不是完整的 CMS 或新闻采编系统，不能替代事实核查和编辑判断。

    成本、准确性与维护

    每一步都调用模型，资料量上来后 API 费用会同步增长；后台提供了预算熔断，但预算和模型选择仍要自己定。摘要和分类可能出错，提示词和门槛需要用本地样本反复校准，不能装完就放任不管。仓库没有 AIHOT 的真实信源名单和运营数据，示范源只有 18 个海外 AI 来源，跑起来能看到流程，不代表直接拥有一个成熟媒体。

    作者说明代码不是精心打磨的通用框架，线上更新会尽量同步但不保证每次同步；模型榜、重置监控等 AI 行业专属功能只留在 AIHOT 线上。许可为 MIT，但 AIHOT 的名称和 Logo 不在授权范围内，二次发布要换成自己的品牌。

    适合的团队

    适合有明确行业信源、懂一点内容运营、愿意持续校准评分标准的开发者或小团队。只想订阅资讯的人，用现成 RSS 阅读器更轻；需要完整采编流程和法务审核的机构媒体，应把 AIHOT 当成辅助工具而不是编辑系统。

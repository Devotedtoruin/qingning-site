last30days：跨平台检索最近 30 天信息并汇总的 Agent Skill

2026年9月12日 · 项目 · 约 5 分钟阅读

更新于 2026年9月16日

跨平台检索最近 30 天信息并汇总的 Agent Skill。

#AI#开源项目#Agent

本页目录

    last30days 是 mvanhorn 维护的 Agent Skill，仓库为 mvanhorn/last30days-skill。它把“最近 30 天”当作检索边界，在 Reddit、X、YouTube、Hacker News、Polymarket、GitHub 等来源里并行搜索同一个话题，再按真实互动和时间排序，交给 agent 合成一份带来源的简报。README 的定位很直接：不是编辑挑选的搜索结果，而是按点赞、观看、赔率这些人群行为排序。按官方 README 整理，未在本机完整实测。

    装好之后，先问一个人或一件事

    Claude Code 走插件市场：

    Codex、Cursor、Copilot、Gemini CLI 等其他支持 Agent Skills 的工具，用通用安装器：

    装好后直接给话题，例如 /last30days Peter Steinberger、/last30days OpenClaw vs Hermes vs Paperclip。它会先解析相关的人、仓库、子版块、频道和话题标签，再多查询并行搜索，把同一件事在 Reddit、X、YouTube 上的讨论合并成一个簇，最后按来源引用。

    零配置能跑，但更多来源要自己接

    Reddit（含评论）、Hacker News、Polymarket 和 GitHub 开箱可用，不需要配置。第一次运行会引导补上 X、YouTube、TikTok、arXiv、Techmeme 等来源所需的钥匙或命令行工具。X 可以用 X_BEARER_TOKEN，也可以登录浏览器会话；YouTube 需要 yt-dlp；TikTok、Instagram、Threads、Pinterest、LinkedIn 和 YouTube 评论走 ScrapeCreators；网页搜索用 Brave。README 给出的免费额度包括 ScrapeCreators 一万次调用、Brave 每月两千次查询，之后按各自规则计费。

    小红书是显式 opt-in，需要本地运行已登录的 x-mcp 浏览器插件或 xiaohongshu-mcp，再用 --search xhs。来源可用性取决于凭据、已安装工具、话题类型和是否主动开启，不是装完就全都有。

    三种不止“查资料”的用法

    第一种是发现模式。问 /last30days what's exploding in AI agents?，它会扫 Reddit 分类、Hacker News 首页、Digg 的 AI 与 Tech 流，必要时加上 X，最后由 agent 过滤垃圾、判断内容价值，给出 5–10 个按速度排序的话题，并附上可直接执行的后继命令。

    第二种是招聘信号。/last30days Listen Labs --hiring-signals 会把当前招聘页面当作公司重心的证据，报告“招聘看起来指向什么”，而不是预测路线图。

    第三种是沉淀与自动化。直接调用引擎可以输出 JSON：

    加 --store 会把结果写入本地 SQLite，配合 watchlist.py 做定时监控，briefing.py 生成日报或周报；library feed 可以把已保存的简报变成本地 HTML 索引和 Atom feed，library search 则离线检索历史简报。

    一个具体场景

    明天要见一位合作方，先跑 /last30days <姓名或公司>。值得看的不是“他最近发了什么”，而是最近一个月的帖子、播客转录、GitHub 提交节奏和 Reddit 上的争议点是否互相印证。重要结论回到原帖或原始视频核对，尤其是数字、引语和带情绪的二手总结。如果结果集中在某一个平台，先检查是来源没启用，还是这个话题本来只在该平台讨论，别急着把缺失当成结论。写选题前也可以用同样方法判断一个工具是否真的有人用，而不是只看发布稿。

    与通用搜索、深度研究的差别

    Google、Perplexity 或通用 deep research 更擅长抓文章、文档和网页；last30days 把论坛投票、视频转录和预测市场赔率放进同一个时间窗口，再按互动量排序。代价是来源更依赖钥匙、cookie 和第三方 CLI，覆盖面取决于你启用了什么。它不是学术数据库，也不适合需要严格引用的正式研究。

    数据与判断的边界

    默认在本机运行，除了向你自己配置的搜索 API 发请求，研究内容不会上传。设置推理 provider 后，话题和检索片段会发给该 provider 做相关性重排；不设 key 时退回本地评分。--store 的 SQLite 也只保存在本地。

    互动量不等于真实性，投票可以被人为放大，预测市场给的是赔率而不是事实。X 官方 API 的近期搜索默认只覆盖约一周，除非开发者项目有完整存档权限，所以“30 天”在 X 上未必成立。第三方来源的条款、额度和隐私政策要自己确认；浏览器 cookie 方案也意味着把登录态交给本地脚本处理。

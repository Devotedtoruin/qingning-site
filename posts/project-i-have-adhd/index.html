i-have-adhd：让 Agent 先给动作、再解释的反啰嗦 Skill

2026年9月18日 · 项目 · 约 4 分钟阅读

更新于 2026年9月22日

让 Agent 先给动作、再解释的反啰嗦 Skill。

#AI#开源项目#Agent

本页目录

    i-have-adhd 是 ayghri 做的一个输出风格 Skill，作者把它称为“ADHD 友好输出”，但 README 开头就写明：不需要真的被诊断为 ADHD。它要解决的问题很具体：coding agent 把答案埋在长篇铺垫里，用户翻了几屏才看到该改哪个文件、该跑哪条命令。

    十条规则把回答改成行动清单

    Skill 的核心是十条规则：

    1. 先给下一步动作。
    2. 多步任务编号。
    3. 结尾只留一个具体的下一步。
    4. 抑制跑题。
    5. 每轮重述当前状态。
    6. 时间估计用分钟，不用“很快”。
    7. 让进展可见。
    8. 报错就事论事。
    9. 列表最多五项。
    10. 不要开场白、不要复盘、不要客套收尾。

    README 的对照例子里，原本的回答先讲认证流程有几个部分，再谈依赖版本，最后问要不要深入；改过之后直接说“编辑 src/auth.ts:42 更新 token 校验”，然后三步操作，最后让你在测试失败时贴第一行错误。信息没有变少，变的是顺序和密度。

    为什么不是单纯说“请简洁”

    “请简洁”通常只减少客套，不会强制 Agent 先给动作、编号、限制列表长度，也不会要求它每轮重述状态。i-have-adhd 把输出结构写进规则，尤其适合排障这种需要不断确认“现在到哪一步”的场景。它还要求把时间估计说成具体分钟，把已经完成的进展明确写出来，减少用户自己在长对话里找线索的负担。想调整规则，直接改 SKILL.md，不需要找额外的图形面板。

    也可以按 INSTALL.md 手动安装。它是一个 Claude Code 插件，装好后用 /i-have-adhd 调用。想改规则就 fork 仓库，编辑 skills/i-have-adhd/SKILL.md，再按 README 的命令卸载旧版、添加自己的 marketplace、重新安装。

    一次连续排障里的用法

    登录接口突然返回 401。默认回答可能先解释 JWT、Cookie 和中间件的关系，再给一堆可能原因。用这个 Skill 后，第一句会落到“先看 src/auth.ts 的 token 校验”，下面三步是打开文件、替换函数、跑指定的测试文件；如果测试失败，结尾只要求贴第一行错误。下一轮它重述当前状态，再给下一个动作。整个过程像一张不断更新的操作卡，而不是一篇教程。

    和默认 Agent、通用简洁提示的对比

    默认 Agent 倾向把推理过程、背景和注意事项一次说完，适合学习，不适合连续操作。通用的“回答简短”提示词能压掉一部分废话，但结构仍由模型自由决定。i-have-adhd 把“先动作、再解释、只推进一步”变成硬规则，代价是牺牲一部分上下文和论证。它和“详细解释”不是谁替代谁，而是两种模式，应该按任务切换。如果只是想要更短的答案，通用提示词就够；如果要稳定的操作结构，才需要它。

    限制与风险

    过度压缩会丢前提。做架构决策、教学讲解、方案对比或需要完整推理链的任务时，这十条规则可能让回答显得过于武断。规则 10 要求不要复盘，在长对话或隔天继续时也可能让状态不完整；这时要主动要求它展开理由或补背景。它也不是医疗建议，ADHD 友好只是作者对输出风格的描述，不能替代诊断或治疗。

    适合被长回答淹没、只想快速推进任务的开发者，尤其是排障、改配置、跑测试这类一步一步做的事。需要完整论证、学习新技术或做高风险决策时，建议换回普通模式，或者明确要求“先给动作，再补一段理由”。

    入口

    仓库：https://github.com/ayghri/i-have-adhd 。安装说明：仓库内的 INSTALL.md，规则原文在 skills/i-have-adhd/SKILL.md。许可证以仓库为准，README 当前标注 MIT。本文按官方 README、安装说明和仓库元数据整理，未在本机完整实测。

archify：把代码库、需求或计划转成可交互架构图的 Agent Skill

2026年9月16日 · 项目 · 约 5 分钟阅读

更新于 2026年9月20日

把代码库、需求或计划转成可交互架构图的 Agent Skill。

#开源项目#AI#Agent

本页目录

    archify 是 tt-a1i 维护的 Agent Skill，官方站点是 archify.si，代码以 MIT 许可发布。它把一句需求、一个计划或一个代码仓库转成可交互的 HTML 图，读图的人能展开节点、沿路径追踪、切换主题，也能把它当成一份可以带走的架构说明。

    先把关系写成结构，再决定怎么画

    常见的 AI 画图流程是让模型直接吐一段 Mermaid，边写边猜布局；archify 改成了另一条路：Agent 先生成带类型的 JSON IR，再由渲染器排版。组件、边界、调用方向、返回关系和证据都落在源数据里，图只是这份数据的视图。官方称其支持十种图：架构、工作流、时序、数据流、生命周期、ERD、类图、树、时间线和瀑布图，每种都有对应的校验规则。

    描述、仓库和解释页三种入口

    没有现成仓库也能用。对 Agent 说“用 Archify 画 Browser 到 API、Redis 和 PostgreSQL 的请求路径”，它会先生成结构，再根据“加上鉴权”“高亮缓存未命中”这类指令继续改。把仓库交给它时，可以限定八到十二个核心组件、一条主路径、外部依赖和信任边界，源证据节点会打开固定提交里的文件和行号，而不是泛泛指向仓库首页。

    第三种用法是“回答成一页”。问题会先给结论，再按子问题拆成面板，把步骤、表格、代码和经过校验的图放在一起；每条论断可以带编号来源，适合排查 P99 延迟、拆解一次请求或做技术选型说明。

    安装与本地命令

    装好后在 Claude Code、Codex、Cursor 或 OpenCode 里直接描述要画的系统。仓库也带一个零依赖 CLI，进入仓库目录后可用于验证和交付：

    validate 会检查 schema、布局、HTML/SVG、路径和标签避让；失败时返回机器可读的诊断和建议修复项。preview 只监听本机回环地址，刷新前会先验证候选文件，验证不过就保留上一份可用结果。

    给老项目补一张能讲清的图

    接手一个没有架构文档的仓库时，先让 Agent 只读入口、路由、数据访问和外部服务，产出一张高层运行时图；确认主路径后，再让它补充鉴权、队列和失败重试。把图发给同事前，用 #focus=、#route= 或 #reach= 固定视图，对方打开就能看到同一个焦点，不用在聊天里反复解释“看右边那个框”。需要汇报时导出 PNG、WebP、JPG 长图或打印成 PDF。

    和 Mermaid、通用画图工具的区别

    Mermaid 适合把结构快速写进 Markdown，Excalidraw 和 diagrams.net 适合手绘和自由排版；archify 的重点是让 Agent 先理解系统，再产出带交互和证据的页面。它明确不把自动解析 Mermaid、通用自动布局、托管分享和所见即所得编辑列进当前范围。换句话说，它不是一个更聪明的白板，而是一条从技术意图到沟通材料的流水线。如果团队已经有 Mermaid 文档，也可以把 archify 的产出当作讲解层，而不是全部替换。

    限制与适合的人

    图里的关系来自代码、描述或计划，不是运行时监控，不能据此判断线上真实流量和故障影响；源代码证据也只在主动要求时才会附上。仓库越大，越需要先限定分析范围，否则图会退化成组件清单。运行环境需要 Node.js 18 以上，Claude.ai 的沙箱还取决于是否有 Node 访问权限。

    适合需要补架构文档、做技术分享、评审方案或交接项目的开发者；如果只想要一张静态示意图，或者需要实时拓扑和 APM 能力，应该选别的工具。

    入口

    仓库：https://github.com/tt-a1i/archify 。官方站与示例库：https://archify.si ，场景指南：https://archify.si/guide.html 。许可证为 MIT。本文按官方 README、站点说明和仓库元数据整理，未在本机完整实测。

静态博客前端：布局与排版

用一份最小文章页实现受限行宽、Grid 收缩、局部横向滚动，以及能在宽窄屏切换的章节目录。

#Hexo#CSS#响应式布局

    长文排版不只是调整字号。代码需要保留空格，数据表需要足够的列宽，目录又不能在手机上抢走整屏空间。把这些内容都交给页面级横向滚动，往往会让整篇文章难以阅读。

    本文用普通 HTML、CSS 和少量 JavaScript 搭一份最小文章页。它包含可直接配合使用的结构、宽度规则和目录折叠逻辑，不依赖框架或 Hexo 专用 API。示例只实现基础布局与目录，不包含滚动高亮、搜索和局部导航；接入具体主题时，需要按真实生成的 DOM 调整选择器。


    搭建文章骨架

    下面是示例页面的 body 内容。目录在文档中先于正文，章节 ID 唯一且稳定；没有脚本时，已有目录链接仍然可以使用。折叠按钮先隐藏，避免脚本加载失败后留下一个没有作用的按钮。

    真实博客可以在构建期生成目录，页面脚本不必再次生成正文。标题、日期和文章内容由模板输出；脚本只是增强目录的交互。



    分配阅读宽度

    先限制页面总宽度，再限制正文行宽。1fr 的自动最小尺寸可能被长代码撑住，正文列使用 minmax(0, 1fr)，Grid 子项再允许缩小：

    72rem 是外层上限，46rem 是阅读列上限，不是适用于所有字体的标准答案。中文可从 16–18px、1.75–1.9 行高开始，再根据字体和行宽调整。窄屏保留一层页边距即可，不必再让正文容器叠加同样宽的内边距。

    position: sticky 还受祖先滚动容器和可用高度影响。目录不吸附时，先检查祖先的 overflow 和布局，不是继续提高 z-index。


    处理代码与表格溢出

    把下面的规则加在前面布局 CSS 之后。正文中的长地址允许换行，代码保留原始空格；表格由包装层负责滚动，不强迫每个单元格都挤进屏幕：

    示例为滚动区加了 tabindex="0"、可见焦点和可访问名称，键盘用户可以定位并滚动它。实际内容没有溢出时，是否需要保留额外 Tab 停靠点，可在增强脚本中根据尺寸决定。

    Hexo 某些高亮器会把代码生成含行号的 table。它不是正文数据表：接入主题时只包装普通表格，排除 .highlight table，并让高亮容器自己处理横向滚动。不应把 .table-scroll table 这组规则全局应用到所有 table。


    生成章节目录

    把下面的脚本放在上述 HTML 之后，或在 defer 脚本中运行。它从实际的 h2/h3 重建目录，依赖模板已经提供唯一 ID，不自行改写可能被外部引用的锚点。文字用 textContent 写入，避免把标题当作 HTML 插入。

    宽度小于 900px 时按钮出现、目录默认折叠，点击后 aria-expanded 与列表可见性同步；达到 900px 后列表始终可见。没有 JavaScript 时，静态目录保持展开，不会失去章节入口。

    这个示例只挂载一次。用于 PJAX 时应封装为挂载函数，并在卸载时移除按钮和媒体查询监听；同一按钮不能在每次换页后重复绑定。



    放置元信息与浮动工具

    发布日期、阅读时长和相邻文章可以在构建阶段生成。阅读时长只是估计，展示到分钟即可，不必模拟精确计时。

    浮动搜索或播放器尽量放在阅读列外，窄屏面板使用视口宽高上限。若底部工具覆盖了正文，应重新安排工具或局部安全间距，而不是给整篇文章增加一大段空白。单独避开页脚也不能保证正文从不被遮挡。


    检验长文布局

    可以在独立示例页中增加一条长 URL、一段长代码和十列表格，按以下结果检查：

    • 在 360px 窄屏，页面本身不横向滚动；代码和表格在自己的容器内滚动。
    • 在 900px 两侧切换，目录按钮、列表可见性和 aria-expanded 一致。
    • 只用键盘能展开目录、跟随锚点并进入滚动区域；焦点始终可见。
    • 禁用 JavaScript，正文与静态目录仍然可读、链接仍可跳转。
    • 放大到 200% 后，标题、按钮和代码没有互相覆盖。

    尺寸与 DOM 检查能验证一部分规则；字体观感、触控滚动和 sticky 的真实行为仍需要在浏览器中观察。

静态博客前端：布局与排版

2026年9月4日 · 前端技术 · 约 7 分钟阅读

更新于 2026年10月22日

用信息栏、正文与目录三列组织长文：宽屏分栏、窄屏单列，代码和表格只在局部滚动。

#Hexo#CSS#响应式布局

本页目录

    新版文章页不再把所有信息塞进一张大卡片。宽屏时，发布日期、分类和阅读时长在左侧信息栏，正文保持可收缩的阅读宽度，目录单独占右侧一列；窄屏时三列依次收拢，目录折叠到正文之前。

    本文用普通 HTML、CSS 和少量 JavaScript 搭出这套骨架。它不依赖框架或 Hexo 专用 API，也不包含滚动高亮、搜索和 PJAX；接入具体主题时，需要按真实生成的 DOM 调整选择器。


    搭建文章骨架

    目录在文档中先于正文，章节 ID 唯一且稳定；没有脚本时，静态目录仍然可以跳转。折叠按钮先隐藏，避免脚本失败后留下一个没有作用的控件。右侧的空目录栏只在宽屏显示，脚本确认存在章节后再把目录移入。



    分配阅读宽度

    先限制整页容器，再限制正文行宽。1fr 的自动最小尺寸可能被长代码撑住；正文列使用 minmax(0, 1fr)，Grid 子项再允许缩小。正文纸面是实色的，背景只在纸面之外可见。

    三列不是固定像素的总和：中间列用 minmax(0, 1fr)，在 1200px 视口里仍能收缩。信息栏只在最宽布局出现，日期和分类不会同时出现在标题下方与左侧栏。中文正文可从 16–18px、1.75–1.9 行高开始，按字体和行宽调整。


    处理代码与表格溢出

    正文中的长地址允许换行，代码保留原始空格；表格由包装层负责滚动，不强迫每个单元格挤进屏幕：

    代码块上方的空白用于语言标签，不再用一条外框把代码包成第二张卡片；表格只保留横向分隔线。Hexo 的高亮器可能生成含行号的 table，接入主题时只包装普通表格，排除 .highlight table。


    生成章节目录

    下面的脚本从真实标题生成条目，宽屏把目录移入右侧栏，窄屏放回正文标题之后。它只读取 textContent，不改写可能被外部引用的标题 ID。

    has-toc 只应在目录确有内容时添加，否则宽屏会预留一列空白。按钮只控制移动端折叠；宽屏目录始终展开。用于 PJAX 时把整段封装为挂载函数，并在卸载时移除媒体查询监听。



    放置元信息与浮动工具

    发布日期、更新时间和阅读时长放在信息栏；标题区只保留标题、摘要与标签。这样宽屏不会在标题下方重复一组日期，窄屏也不需要额外折叠。

    浮动播放器或返回顶部按钮应避开正文和目录的阅读区域。窄屏面板使用 100dvh 上限，底部预留安全区；播放器收起时只占一个小胶囊，展开时也不应覆盖整列目录。


    检验长文布局

    在独立示例页加入一条长 URL、一段长代码和十列表格，按以下结果检查：

    • 1440px：信息栏、正文、目录三列；目录 sticky，正文行宽稳定。
    • 1200px：三列仍能放下，中间列没有被长代码撑破。
    • 1024–1199px：信息栏收起，正文与目录两列；日期回到标题下方。
    • 768px 与 390px：单列，目录在正文之前折叠；页面本身不横向滚动。
    • 只用键盘能展开目录、跟随锚点并进入滚动区域；焦点始终可见。
    • 禁用 JavaScript，正文与静态目录仍可读、链接仍可跳转。

    尺寸和 DOM 检查只能验证规则；字体的实际观感、触控滚动和 sticky 行为仍要在浏览器中观察。

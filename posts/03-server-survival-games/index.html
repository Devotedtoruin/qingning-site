Server Survival 与 Datacenter Survival：请求与机房

两款开源浏览器游戏的项目背景、试玩地址与基本玩法：搭云服务架构，或经营机房供电与散热。

#开源项目

Server Survival 和 Datacenter Survival 是开发者 Kostyantyn Pshenychnyy（pshenok） 制作的两款开源浏览器游戏。一个让玩家搭云服务架构，另一个把视角移到服务器背后的供电和散热。按照下方固定版本的官方说明，两款都可直接在网页游玩，不用注册账号。

Server Survival：云服务架构

画布上的节点代表负载均衡、计算服务、数据库、缓存和消息队列，移动的小球代表请求。玩家购买组件、连接流向，让合法请求得到处理，同时守住预算、声誉和服务健康度。组件持续产生维护成本，并不是堆得越多越好。


开始可选 Campaign，按关卡目标理解组件；该版本包含 25 关、5 章。Survival 在不断上涨的流量和随机事件下考验架构，Sandbox 则允许调整预算和流量，没有常规的游戏结束压力。关卡起始布局与任务不同，不需要先照搬一套庞大的通用拓扑。



游戏把 CDN、缓存、只读副本、队列和扩容做成可连接的节点：静态请求可交给 CDN，缓存或副本分担读负载，队列缓冲突发请求，Firewall 处理恶意流量。组件的适用请求类型与成本不同，先看失败标记和当前目标，再决定补哪一环。

左键选择和放置组件，C 切换连线工具，连接有方向；右键拖动画面，滚轮缩放，R 重置视角。可以先暂停时间搭好路径，再用一倍速查看请求走向。



Datacenter Survival：机房供电与冷却


这次的组件是市电、变压器、UPS、PDU、机架和冷却设备。机架有电且温度合适时才能持续带来收入；供电链任何一环容量不足，都可能影响下游负载，严重过载还会触发断路器。UPS 负责短时接续，备用发电机则受启动和燃料限制。

机架耗电产生热量，冷却设备自己也消耗电力。除了给机架降温，还要平衡设备规模、PUE 和费用；T 键可切换热力图。CRAC 适合局部冷却，Chiller 与 CRAH 则引入共享冷水系统，不是规模越小也越划算。

该版本 Campaign 有 13 关；The Lab 提供已接好的供电链，包括 UPS、备用发电机、三个机架和一个 CRAC，还能手动触发停电、热浪或冷却故障。想先认识设备，可从 The Lab 开始；想按目标逐步搭建，则进入 Campaign。



两款游戏怎么选

喜欢画服务拓扑、调请求分流和扩容，选 Server Survival；对供电支路、UPS 接续和机房温度更感兴趣，选 Datacenter Survival。两款都提供自由观察的模式，不必先安装服务端或准备真实云资源。

    Ubuntu 24.04 云服务器初始化：SSH 安全与基础维护

    #Ubuntu#SSH#安全#APT

    本文以 Ubuntu Server 24.04 为例，完成普通管理员、公钥认证、SSH 端口迁移和基础软件维护。操作涉及 Windows 管理端、云网络控制台和服务器终端。修改 SSH 时保留控制台或现有会话，确认新连接可用后再关闭旧入口。

    适用范围、风险与变量

    适用于 Ubuntu Server 24.04。开始前准备云控制台或可用的初始 SSH 会话，并预留一个新的 PowerShell 窗口测试连接。示例变量按实际环境填写。

    变量 含义 操作位置
    ADMIN_USER 普通管理用户 服务器
    SERVER_ADDR 服务器公网地址或域名 PowerShell
    OLD_SSH_PORT / NEW_SSH_PORT 迁移前后 SSH 端口 控制台、服务器、PowerShell
    KEY_FILE Windows 私钥文件名 PowerShell

    1. 建立独立密钥和普通管理用户

    在 Windows PowerShell 创建一套服务器专用密钥。公钥文件默认在私钥路径后追加 .pub；私钥只保留在管理端。

    在保留的初始服务器会话中创建用户。adduser 会交互设置服务器本地密码；不要记录或公开该密码。将 PowerShell 中读取的单行公钥粘贴到 heredoc 内。

    若登录失败，在旧会话或控制台检查用户名、公钥是否完整，以及.ssh和authorized_keys的属主与权限。修复配置后重新测试，不要先删除唯一可用的授权。

    3. 仅允许公钥认证

    确认新端口公钥登录正常后再收紧认证策略，并继续保留一个已登录会话。先查看现有配置；Ubuntu 的 OpenSSH 配置可能受多个文件影响，最终以sshd -T输出为准。

    上述括号创建子 Shell；备份、写入或语法检查失败会终止本块，不会继续 reload，也不会退出保留的交互会话。sshd -T 输出还需人工核对；如有 Match，使用 sudo sshd -T -C 'user=root,addr=<客户端地址>,host=<客户端主机名>' 等对应连接条件检查有效策略（先替换占位符），不要只看全局值。

    常见问题与最终验收

    现象 先检查什么 不能据此断定什么
    新端口超时 网络规则、ss、管理端地址 不能只凭超时认定是安全组问题
    新用户被拒绝 公钥、权限、用户名、日志 本地文件存在不等于登录成功
    sshd -t 成功 再看 sshd -T 语法成功不等于策略生效
    systemctl 非零 systemctl --failed 不自动等于系统不能维护

    完成后确认：普通管理员可以通过新端口和公钥登录并使用 sudo；旧端口已经关闭；密码与 root 远程登录被拒绝；软件更新和服务状态无异常。

    Ubuntu 镜像和云平台的默认配置可能不同。修改前先查看当前 SSH unit 和生效配置，并始终保留控制台或已有会话。

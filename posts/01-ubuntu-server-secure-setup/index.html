Ubuntu SSH：公钥登录与端口迁移

在 Ubuntu 24.04 创建管理用户、配置公钥登录，再按 socket/service 分支安全迁移 SSH 端口。

#Linux#SSH#服务器安全

    配置 SSH 可以分成三项任务：建立普通管理账号、让公钥认证可用、迁移监听端口。先完成账号和密钥，再改变网络入口，最后关闭不需要的认证方式，遇到问题时更容易判断是哪一层出了差错。

    本文适用于已安装 OpenSSH Server、使用 systemd 的 Ubuntu Server 24.04。你需要一个当前可用的管理账号及 sudo 权限、一台带 OpenSSH 客户端的电脑，以及独立于 SSH 的服务器控制台。不同云镜像的初始账号、认证策略和 socket 激活状态可能不同，操作前以实际配置为准。以下命令是配置示例，不代表已经在你的服务器上执行。更换端口能减少部分扫描噪声，不能代替公钥认证、更新和网络访问控制。

    平滑迁移 SSH 端口

    迁移顺序是：先放行新端口 → 同时保留新旧监听 → 从外部建立新连接 → 移除旧监听 → 收紧旧网络规则。

    先放行网络，再改监听

    先在云安全组或上游防火墙中允许管理来源访问新 TCP 端口，保留旧规则。再检查主机防火墙；云规则和主机规则必须同时允许，修改其中一处不会自动修改另一处。

    如果服务器已经启用 UFW，可先查看规则，再按实际管理来源增加新端口：

    预期规则列表包含该来源到新端口的允许规则。UFW 未启用时，不在远程迁移中直接运行 ufw enable；使用其他防火墙的服务器应按其现有规则管理方式放行。

    确认新入口可用后，在实际生效的 socket drop-in 或 sshd 配置中移除旧端口，按对应分支重新应用。用 ss 确认旧监听消失，再删除或收紧旧端口的网络规则；不要删除仍供其他服务使用的规则。

    连接失败时恢复

    新连接超时，先看安全组、主机防火墙和监听地址；连接被拒绝，先看端口是否真的在监听；Permission denied 则检查用户名、公钥与认证日志。这些现象帮助缩小范围，不单凭一条错误就认定根因。

    旧连接还在时，保留双端口配置并逐项检查。已经失联则进入控制台，对照备份恢复原文件：恢复原有内容，撤去本次新增但备份中不存在的配置，再按原分支应用。socket 分支需要 daemon-reload 及对应单元重启，service 分支在语法检查后重载。恢复监听后从外部重新连接，不只在控制台看状态。

    软件索引、工具、升级与重启

    SSH 入口稳定后，再安排系统更新，不把网络迁移、升级和重启挤在同一次操作里。服务器上先刷新索引并查看待升级列表：

    apt update 只更新软件索引。确认维护窗口及变更后，运行 sudo apt upgrade，阅读交互摘要再决定是否继续；不在教程中用自动确认掩盖可能的服务重启。

    需要重启时先确认控制台和新 SSH 入口仍可用，安排维护时间后再重启。机器重新上线后，重新检查端口、普通账号公钥登录和 sudo。

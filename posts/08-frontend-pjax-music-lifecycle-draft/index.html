    静态博客前端（三）：PJAX 插件生命周期与持续音乐

    从只替换 main 的导航边界出发，区分全局与每页插件，处理异步竞态、播放器状态、历史回退和失败降级。

    #渐进增强#JavaScript#PJAX#音频

    静态站点也可以在站内跳转时保留播放器，但关键不是“记住播放秒数”，而是不要销毁正在播放的那个 audio 元素。与此同时，目录、复制按钮和图片灯箱属于旧文章，不能因为页面没有完整刷新就一直留下来。

    本文依据本站 pjax.js、site.js 与 music.js 的源码讲解维护方法。本文区分源码中已经实现的保护与读者仍应执行的验收场景，不把代码阅读当作真实连续播放测试。标注为教学模型的示例不代表主题的完整接口。

    先确定什么会被替换

    本站 PJAX 以 main 为替换边界：获取同源 HTML，解析出新 main，替换旧正文，再同步页面标题与部分元信息。页头、页脚和放在 main 外的播放器可以保留。持续音乐依赖播放器节点身份不变，而不是在换页后重新创建音频并跳到旧时间。

    全局生命周期和每页生命周期分开

    滚动进度、回到顶部、固定页头和播放器属于长期保留的界面；目录、文章表格、复制按钮及文章媒体则依赖当前正文。前者通常只安装一次，后者每次换页重新挂载，并在旧页离开时清理引用和外部监听。

    本站已使用 WeakSet 或 WeakMap 去重部分 DOM 初始化。去重能避免同一节点出现两个复制按钮，却不能自动解决所有资源泄漏：挂在 window 上的旧目录滚动监听，仍可能保留已移除标题的引用；IntersectionObserver、超时回调和灯箱也需要明确释放。

    请求取消与“最后一次导航获胜”是两道保护

    快速点击文章 A、B 时，A 的响应可能晚于 B。如果只按响应顺序替换页面，会回到用户已经放弃的页面。本站导航器使用 AbortController 取消前一个请求，同时用递增的导航标识检查响应是否仍属于当前导航。

    两者不能互相替代：取消是尽量停止工作，版本标识是防止过期工作提交结果。插件脚本加载、缓存响应或已经开始的 Promise 回调，都不一定随 fetch 取消而消失。每次异步完成前，应再次核对导航标识与当前 main 的身份。

    导航失败应保留普通页面跳转。本站对 HTTP 错误、非 HTML、缺失 main 和超时采用整页导航回退；这会重建 audio，因而音乐可能停止。正确的产品说明应是“受支持的 PJAX 站内切换持续播放”，不是“任何跳转都不断”。外站、新标签页、刷新和失败回退也不在保持范围内。

    插件失败不能阻塞正文

    图片灯箱是增强功能，原图链接才是基本入口。当前 PJAX 代码在正文替换后调用本地模块，再异步准备文章所需的 PhotoSwipe；可选加载失败不应让整篇文章无法进入。脚本超时或库缺失时，图片仍应能直接打开。

    不过插件需有可重复挂载的边界。库晚到时第二次 mount，应增强当前文章，而不是给旧文章绑定监听；从文章回列表时，也不应保留遮罩、锁滚动状态或焦点陷阱。当前顺序是关闭搜索、销毁每页工具与日历、替换正文，再重新挂载当前页面；可选媒体库准备完成后还要检查导航标识与 main 身份。media.js 在 mount 时扫描已脱离文档的旧文章，调用动画清理与 gallery.destroy，再从集合和 WeakMap 移除。这里是下次挂载时清理，不是浏览器自动释放所有全局状态。

    不能只验收首页直接打开的文章。至少要走首页 → 文章 → 列表 → 另一篇文章，重复数次，再检查复制按钮数量、目录高亮、表格容器和灯箱关闭后的焦点返回。

    音乐是一套异步状态，不是一个播放图标

    播放器默认没有音源、preload="none"，首次展开后准备本地音源；播放仍由用户主动点击开始。展开界面、加载源和开始播放是不同动作。浏览器可能拒绝 play()，网络可能进入 waiting，音频可能自然结束，因此不能在调用 play() 的瞬间直接把界面永久画成“正在播放”。

    源码使用以下状态：用户是否想继续播放、播放 Promise 是否待完成、是否缓冲、是否出错，以及当前请求编号。应从真实媒体事件和最新用户意图一起推导显示状态：缓冲时不旋转唱片，暂停后旧 Promise 的成功回调不应把界面改回播放。

    特别容易出现的竞态是：用户点击播放，立即暂停，再选择另一首；第一首的 Promise 晚到。递增请求编号能让旧回调失效，但还应结合 playing 事件与实际媒体状态，防止音频本身继续发声而界面显示暂停。这里不声称本文已经完成这组实测。

    曲目地址应来自受控本地列表，不能把用户参数任意转成音源。当前 safeAudioUrl 限定本站 /audio/ 路径和 MP3/OGG 格式，并排除查询串、片段、路径穿越等不符合规则的输入。这是特定站点的输入约束，不是适用于所有 URL 的通用安全解析器。

    自然续播不能绕过主动播放与暂停

    多曲目列表可以在自然结束后继续下一首，但前提应是用户已经主动播放且没有撤回意图。单纯收到 ended 事件不能作为“随时自动播放下一首”的许可；暂停、错误、换曲请求失效时应清除续播资格。

    当前代码在 playing 后允许自然续播，并在暂停或错误时清除；多曲目使用下一项循环。多曲目以 (index + 1) % entries.length 回到下一项，最后一首自然结束后回第一首；只有一首时停止。播放请求等待期间再次点击暂停，会撤回意图并让旧请求失效；错误后由用户重试。不要把它描述成浏览器一定允许的自动播放保证。

    播放器可以点触发按钮收起，也会在根节点外 pointerdown 或 Escape 时收起；这些入口只隐藏面板、更新 aria-expanded，不暂停、不归零。收起前焦点位于面板内部时，返回触发按钮。点击面板内进度或曲目不属于外部点击，不能意外关闭。切页时保留同一个 audio。减少动态效果只应停止唱片装饰动画，不应该自行停止用户选择的音乐。键盘进度控制还需要有效时长、有限数值和范围校验，未知 duration 时不能计算 NaN 百分比。

    历史记录、锚点与焦点是导航的一部分

    PJAX 替换了正文，却没有浏览器整页加载自动提供的全部语义。需要处理标题、canonical、描述等元信息，前进后退的页面状态、滚动位置，以及当前页面锚点。本站导航器维护 history 状态与滚动位置，并区分普通进入和历史恢复；同页片段通常交给目录或原生行为。

    目录更新 hash 时不能无条件覆盖整个 history state，否则导航器保存的信息会丢失。返回入口也不能只看 referrer：它可能为空或来自外站；缺少有效站内来源时，仍需一个明确的文章列表链接。

    还有一项不能遗漏的验收是焦点：新页面进入后，用户是否知道正文已改变；后退是否恢复可预测位置；搜索关闭后焦点是否回到触发入口。本文不把“URL 变了”当成可访问导航已完成，最终行为仍需实际键盘与辅助技术检查。

    把成功路径和失败路径分开验收

    1. 首次进入时没有自动音频请求或自动播放；展开、播放、暂停分别符合文案。
    2. 支持的站内切页后 audio 节点保持不变，播放位置继续，页面工具更新。
    3. 播放 Promise 被拒绝、缓冲和错误时，按钮、状态文案与旋转动画一致。
    4. 快速播放/暂停/换曲与自然结束不会让旧请求恢复播放或覆盖新曲目。
    5. 快速导航只显示最后选中的页面，取消不会触发旧页面的整页跳转。
    6. 前进后退、文章锚点、返回入口、标题与元信息正确。
    7. 可选媒体库加载失败仍可阅读并打开原图；导航失败转为普通跳转。
    8. 重复换页后没有重复目录监听、复制按钮、表格包装或遗留灯箱状态。

    维护规范已区分 PJAX 站内切换与完整页面跳转：前者保留同一个音频实例，后者会重建页面并中断音乐。收起仅隐藏界面，暂停由明确按钮控制。播放连续性与缓冲反馈仍须在真实网络条件下验收，源码阅读并没有给出无缝播放的测量结果。

    实现依据为主题 source/js/pjax.js、source/js/site.js、source/js/music.js 与播放器所在模板。延伸参考：MDN：HTMLMediaElement.play()、MDN：History API、MDN：AbortController。源码核对日期为 2026-10-13。上述清单是可重复使用的验收方法，不是已经完成的测试日志；本文不提供未执行的线上结果。

FanBox：把文件、终端和改动放进一个驾驶舱

2026年9月19日 · 项目 · 约 5 分钟阅读

更新于 2026年9月23日

vibe coding 驾驶舱：文件、终端和改动一起看。

#AI#开源项目#Agent

本页目录

    FanBox 是花叔 Huashu 做的 macOS 桌面应用，定位是 coding agent 的“驾驶舱”：左边浏览文件和预览，右边或下方跑真实终端，中间用一块面板看清 Agent 这一回合改了哪些文件。它不是又一个 IDE，而是把“找回项目、启动 Agent、验收改动”这条链路收进一个窗口。

    一条从文件到验收的路径

    文件区支持 ⌘K 模糊搜索，输入 内容:关键词 会切到全文搜索，⌘↵ 可以用外部编辑器打开整个项目。Markdown、HTML、代码、图片、视频、PDF、HEIC 和压缩包都能原地预览；文件夹卡片会标出 node、web、py、rs、go 等项目类型，适合同时开了很多小项目的人。

    真正区别普通文件管理器的是“跟随”和“本回合”。开启跟随后，预览会跟着 Agent 正在写的文件走：代码滚动到新写入的行，HTML 边写边渲染，Markdown 实时更新；一旦你手动浏览，控制权立刻回到手里。本回合面板按终端和 Agent 分组，列出改动文件与增删行数，点开是 Monaco 的并排 diff，可以还原单个文件、回滚整回合，也可以拖动底部时间轴回放。Markdown 还能按渲染后的“读者视图”对比，图片则给前后滑杆。

    终端与 Agent 状态

    内嵌终端基于 node-pty 和 xterm.js，能正常跑 Claude Code、vim、htop 和中文宽字符。把文件从列表拖进终端，会插入路径作为上下文；终端输出里的路径可以点击回打开。FanBox 启动 Claude Code 或 Codex 时会挂上它们的官方 hooks，因此“正在干活、等你确认、等你输入、已完成”是事件而不是猜终端文字。两个以上终端同时开着时，标签栏下会出现“在等你”的会话列表，⌘⌥L 可以跳到下一个需要你的会话。

    内置 11 个 Agent 启动器，包括 Claude Code、Codex、Hermes Agent、OpenClaw、Kimi Code、opencode 等，默认只显示 Claude Code 和 Codex。未安装的条目可以一键复制安装命令；~/.fanbox/config.json 的 agents 数组可以改命令或追加新 Agent。

    安装与运行

    桌面版从 GitHub Releases 下载 .dmg，拖进“应用程序”。官方构建是 Apple Silicon 原生，已签名、公证，双击即可打开。Windows 只有社区移植版，作者明确表示自己没有 Windows 机器，无法为体验和安全负责，使用前要自行评估。

    只想快速看文件时，可以跑网页版：

    然后打开 http://localhost:4567。网页版零依赖、零构建，但只有浏览、搜索和预览；终端和编辑器依赖 Electron。开发模式则是 npm install 后执行 npm run app。

    一个“下午起了十个项目”的场景

    Agent 很快就能生成一堆小项目，麻烦的是第二天回来找不到哪个目录对应哪个想法，也记不清昨天改了哪些文件。FanBox 的项目记忆会按文件夹列出历史会话，用你的第一句话当标题，并显示每次会话改过的文件；点“续上”会在内嵌终端执行 claude --resume 或 codex resume。看到本回合的 diff 后，可以直接在行上写批注，再以“文件:行 + 代码围栏 + 批注”的格式粘回 Agent 终端。

    和 VS Code、Finder 的分工

    Finder 负责文件管理，VS Code 负责编辑和插件生态，FanBox 把精力放在找回、预览、轻改和指挥 Agent 上。它不跟 Finder 拼文件操作，也不跟 VS Code 拼编辑器；没有云、远程和账号，后端只监听本机回环地址。若你的主要工作是写代码和调试，完整 IDE 仍然更合适；若主要工作是盯着多个 Agent 产出并验收，FanBox 的界面更贴近这条流程。

    限制与风险

    官方目前只支持 macOS，Windows 版本不是作者维护。它也不是完整 IDE，网页版缺少终端和编辑能力。AI 整理只用元数据生成提案，不读文件内容，但仍应逐条确认后再执行；删除走系统废纸篓，重要项目还是要有独立备份。用量面板会访问 Claude 和 Codex 的官方额度接口，更新检查会访问 GitHub，完全离线时这些功能不可用。

    适合长时间与 Claude Code、Codex 协作、经常需要看 diff 和回滚的开发者，以及同时维护多个小项目的人。只用单个 Agent、单个仓库的简单脚本工作流，可能感受不到它的价值。

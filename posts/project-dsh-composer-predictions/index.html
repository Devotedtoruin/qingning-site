composer-predictions：DSH 输入预测插件

2026年10月18日 · 项目 · 约 4 分钟阅读

更新于 2026年10月22日

DSH 输入预测插件，按 Tab 填入下一条提示词。

#AI#开源项目#Agent

本页目录

    composer-predictions 是 boshihaihai 做的 DeepSeek Harness（DSH）插件，仓库为 boshihaihai/dsh-plugin-composer-predictions。助手回答结束后，它会根据当前对话推荐下一条提示词，以浅色文字显示在输入框内；按 Tab 填入草稿，编辑后自行发送。README 说明它受 Codex 的输入预测交互启发，是一个独立的 DSH 插件。按官方 README 整理，未在本机完整实测。

    输入框里的下一条建议

    推荐内容只在输入框为空时显示。开始输入、按 Esc 或切换会话都会取消当前建议。这样的限制避免它和正在写的内容打架，也避免旧会话的建议被带到新话题里。

    开关在“设置 → 通用 → 显示输入预测”，默认开启。插件使用当前会话的模型生成推荐，每次推荐会增加一次模型请求；如果模型没有生成有效推荐，或者请求超时，输入框里不会出现提示。推荐会沿用用户当前使用的语言，不会突然切成英文。

    安装与版本适配

    安装包从 Releases 下载 .tgz，然后在 DSH 左侧“插件 → 添加插件”里填入安装包的完整路径，安装并启用后重启 DSH。README 给出的更新方式是先卸载旧版，再安装新版。

    接口适配写明基于 DSH Desktop 2.0.17-beta.2 / dsh 0.2.1-alpha.2。DSH 插件接口仍在变化，装之前先确认自己的版本是否在这两个版本附近；版本差太多时无法保证适配。如果升级 DSH 后插件没有反应，优先回退到适配版本或等插件更新，不要在工作区里反复重装。

    一个连续工作流场景

    如果每天重复同一套流程，例如“看 diff → 改问题 → 跑测试 → 更新变更说明”，每一轮结束后的下一步往往可以预料。助手回复完，插件给出“继续修下一个问题”或“跑一遍测试”之类的建议，按 Tab 接受，改几个字再发送。高频连续对话里，省下的是反复组织同一句话的时间。

    探索性任务不适合依赖它。话题还没收敛时，最有价值的下一步往往不是模型能猜到的，建议反而会把人往默认路径上带。

    判断是否值得装，可以看两个指标：一天里有多少轮对话的下一步是重复的，以及这些对话对延迟是否敏感。前者高、后者低，收益最明显；如果每轮都要重新判断方向，建议只会增加噪音。

    与提示词模板库、行内补全的差别

    提示词模板库要求你事先整理常用指令，适合固定任务，但换一个上下文就要手动挑。代码编辑器的行内补全补的是代码，不负责下一轮对话的意图。composer-predictions 补的是对话层面的下一步，位置在输入框，不替你执行，也不自动发送。

    任务规划仍然由 agent 负责，预测只是把一句话填进草稿，是否采纳、要不要改，仍由使用者决定。

    成本与误判

    每次推荐都是一次额外的模型请求，频繁使用会增加延迟和费用；对话很长时，这个成本更明显。预测可能把用户推向模型熟悉的套路，重要操作、破坏性命令和涉及外部系统的步骤不能因为按了 Tab 就直接发送。

    插件发布不久，README 只写了两个适配版本，没有展开隐私和数据处理细节，只说明使用当前会话模型。处理敏感对话前，先确认 DSH 和模型提供方的数据策略。输入框非空时不显示建议、切换会话会取消，这些行为也意味着它不适合用来保存跨会话的待办。
